# V2 dark mode

V2 components and the documentation support Light, Dark and System. The preference persists locally; the initial document applies it before first paint. Theme changes synchronize existing and newly loaded preview frames without changing their source URLs, props or state.

## Compatibility boundary

V2 uses isolated `--v2-*` roles and `v2-semantic-*` Tailwind colors. Light values fall back to the original semantic palette. Native v1 source, public APIs and compatibility waivers are unchanged. Migration comparisons retain v1's original light appearance. Put `.dark` on the document root so body portals inherit the same palette.

`src/styles/v2-theme.css` is canonical. Registry generation embeds it into the CLI init theme; the library imports the same stylesheet. Compile the updated unprefixed Tailwind configuration when installing v2. Opacity utilities use color-mix so compiled `/40` classes remain available.
